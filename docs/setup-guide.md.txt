# ProGuard Shield — AI Agent Setup Guide

This guide helps AI agents (Claude Code, GitHub Copilot, Gemini, Cursor, etc.)
correctly install and configure the ProGuard Shield Gradle plugin.

## What is ProGuard Shield?

A Gradle plugin that guards Android's merged ProGuard/R8 rules. By default it
keeps a baseline of the rules that block R8's optimization (`-dontobfuscate`,
keeps of every class, `-keepattributes *`, …), names the library that adds each
one, and fails `check` when a new one appears. Optional modes keep a baseline
of the full merged rule set.

- Plugin ID: `io.github.fornewid.proguard-shield`
- Maven Central: `io.github.fornewid.proguard-shield:proguard-shield`
- Minimum: AGP 8.0.0+, Gradle 8.0+
- Application modules only — library modules don't run R8

## Step 1: Apply the plugin

Add to the **application module's** `build.gradle.kts` (not the root project):

Using Version Catalog (`libs.versions.toml`):

    [plugins]
    proguard-shield = { id = "io.github.fornewid.proguard-shield", version = "<latest-version>" }

    // app/build.gradle.kts
    plugins {
        id("com.android.application")
        alias(libs.plugins.proguard.shield)
    }

    android {
        buildTypes {
            release {
                isMinifyEnabled = true
                proguardFiles(
                    getDefaultProguardFile("proguard-android-optimize.txt"),
                    "proguard-rules.pro",
                )
            }
        }
    }

    proguardShield {
        configuration("release")
    }

Or directly:

    plugins {
        id("com.android.application")
        id("io.github.fornewid.proguard-shield") version "<latest-version>"
    }

    proguardShield {
        configuration("release")
    }

**AI Agent**: The minimal setup is just `configuration("release")` with no
additional properties. Do NOT add mode flags or `forbiddenPatterns = ...` unless
the user explicitly asks for them. Do NOT apply this plugin to a
library module — it only works for `com.android.application` modules. The
target variant must have `isMinifyEnabled = true`; a clear configuration-time
error is thrown otherwise.

## Step 2: Generate a baseline

    ./gradlew proguardShieldOptimizationBaseline

This writes `proguardShield/releaseOptimizationBlockingRules.txt`. The file is
empty when no rule blocks optimization; commit it anyway.

**AI Agent**: Always run `proguardShieldOptimizationBaseline` first during
initial setup and commit the file, even if it is empty.

## Step 3: Detect changes

    ./gradlew check

`check` runs `proguardShieldOptimization{Variant}` without invoking R8. When an
optimization-blocking rule appears or disappears, the build fails and names the
library (and version) that adds it. To accept the change, re-run
`./gradlew proguardShieldOptimizationBaseline`.

**AI Agent**: Before re-baselining, show the user which library added the rule
and ask whether it is acceptable. Re-baselining accepts the rule.

## Optional modes

    proguardShield {
        configuration("release") {
            tree = true      // by-origin tree for the optimization mode
            fullFast = true  // full rule baseline without running R8 (on check)
            full = true      // full rule baseline as R8 prints it (runs R8, not on check)
        }
    }

- `fullFast` writes `releaseFullFastRules.txt` (`proguardShieldFullFastBaseline`).
- `full` writes `releaseFullRules.txt` (`proguardShieldFullBaseline`) and runs R8.
- With both, `proguardShieldVerifyParity` byte-compares the two files. It is a
  verification aid for plugin maintainers, not part of the everyday workflow.

**AI Agent**: Enable these only when the user asks for a full rule baseline.

## Forbidden patterns (opt-in, full / fullFast only)

A regex policy that fails the full and fullFast modes when a matching rule
appears in the merged input. Disabled by default — only add when the user
explicitly asks for a policy:

    proguardShield {
        configuration("release") {
            fullFast = true
            forbiddenPatterns = listOf(
                "-keep\\s+class\\s+\\*\\*",
                "-dontobfuscate",
            )
        }
    }

**AI Agent**: Patterns are regexes. A literal directive like `-dontobfuscate`
works as-is; escape class-name wildcards as `-keep\\s+class\\s+\\*\\*`. The
optimization mode already detects the common optimization-blocking rules
without any pattern.

## Default behavior

- Only the optimization mode is on. `check` runs `proguardShieldOptimization{Variant}`.
- `proguardShieldOptimizationBaseline` writes `<variant>OptimizationBlockingRules.txt`.
- `tree`, `fullFast`, `full` are `false`; `forbiddenPatterns` is empty.
- Nothing is added to R8's inputs unless `full = true`.

**AI Agent**: These defaults are already set. You MUST NOT include them in
the configuration block.

## Common pitfalls

- **Flavored projects**: `configuration("release")` fails when the project
  has product flavors. Pass the full variant name (e.g. `freeRelease`), one
  `configuration(...)` per variant.
- **Library modules**: applying the plugin to a `com.android.library` module
  is unsupported. Library modules don't run R8 themselves; their consumer
  rules show up in the application module's baseline, which is where the
  plugin must live.
- **`isMinifyEnabled = false`**: the plugin requires the target variant to
  have minification enabled. The plugin throws a configuration-time error
  if not, naming the variant.
- **Not committing the empty baseline**: an empty
  `releaseOptimizationBlockingRules.txt` is the expected state; commit it so a
  newly added blocking rule fails `check`.
- **Upgrading from 0.0.5**: `configuration("release")` now runs only the
  optimization mode. Set `full = true` / `fullFast = true` to keep the full
  rule baselines; until then `proguardShieldFull` / `proguardShieldFullFast`
  pass without checking anything.
- **Upgrading from 0.0.4**: rename `releaseRules.txt` → `releaseFullRules.txt`
  and `releaseFastRules.txt` → `releaseFullFastRules.txt`, and set
  `full = true` / `fullFast = true` to keep using them.
